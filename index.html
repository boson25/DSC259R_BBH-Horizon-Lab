Introduction

In this project, we analyze a recipe dataset containing over 80,000 recipes, with features such as tags, descriptions, cooking time, number of steps, number of ingredients, and nutrition information. Our central question: can we predict whether a recipe is healthy using only the recipe's metadata — without peeking at nutrition data?

02

Data Cleaning & EDA

We define a recipe as healthy if it satisfies at least three of four median-based nutrition conditions: low calories, low sugar, low saturated fat, and high protein. This creates a binary target where 1 = healthy and 0 = unhealthy.

Nutrition variables used to define the label are excluded from model features to prevent data leakage. We rely instead on recipe tags, description text, cooking time, number of steps, and number of ingredients. The dataset is imbalanced (~70% unhealthy, ~30% healthy), so we use ROC-AUC as our primary evaluation metric.

Assessment of Missingness

Columns with missing values in the cleaned dataset: name, description, and avg_rating. We argue that missingness in description is likely NMAR — whether a user writes one may depend on the content itself. Simple, quickly-submitted recipes are more likely to omit a description.

A permutation test showed avg_rating missingness is significantly related to cooking time (observed mean diff: 117.34 min, p = 0.038) and even more strongly to n_ingredients (p ≈ 0). This suggests avg_rating missingness is at least partially MAR — simpler, faster recipes are more likely to have missing ratings.

04

Hypothesis Testing

H₀ — Null Hypothesis

There is no difference in average rating between short recipes (<30 min) and long recipes (>60 min).

H₁ — Alternative Hypothesis

There is a meaningful difference in average rating between short and long recipes.

Using a permutation test with 2,000 shuffles, we found an observed mean difference of 0.0359 points (short minus long) and a p-value below 0.0005. We reject H₀ at the 0.05 significance level — short recipes tend to receive slightly higher ratings.

The effect size is small: statistically significant but not large in practical terms. A second test comparing low- vs. high-ingredient recipes found no significant difference in average rating.

H₀ — Null Hypothesis

The number of ingredients is not associated with average rating. Any observed difference is due to random chance.

H₁ — Alternative Hypothesis

The number of ingredients is associated with average rating.

We split recipes into low-ingredient (≤ median) and high-ingredient (> median) groups and ran a permutation test with 2,000 shuffles. The observed mean difference was 0.004 points (low minus high) with a p-value of 0.407.

Since p > 0.05, we fail to reject H₀ — there is no statistically significant evidence that the number of ingredients is related to average rating.

05

Framing the Prediction Problem

We frame this as a binary classification problem: predict whether a recipe is healthy (is_healthy = 1 if ≥ 3 of 4 nutrition conditions are met). We evaluate with ROC-AUC to account for class imbalance (~69.5% unhealthy, ~30.5% healthy).

Features used — selected carefully to avoid data leakage:

  • Tags — TF-IDF encoded tag strings (health-related tags like "healthy" and "low-fat" are highly informative)
  • Description text — TF-IDF encoded free-text description
  • Structural features — cooking time (log-transformed), number of steps, number of ingredients
06

Baseline Model

Our baseline is a logistic regression using only n_steps, n_ingredients, and log_minutes. At ROC-AUC 0.5844 — barely above chance — structure alone is a weak predictor. Adding TF-IDF tags jumped performance to 0.7542; adding description text raised it to 0.7642. Textual metadata carries far more signal.

Final Model

Comparing logistic regression (0.764), random forest (0.768), and gradient boosting (0.769) on the full feature set, Gradient Boosting came out on top. Our final pipeline adds n_steps_sq (squared steps captures non-linear complexity) and tunes via GridSearchCV: learning_rate = 0.1, max_depth = 5, n_estimators = 200.
