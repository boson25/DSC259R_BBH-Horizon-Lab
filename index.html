A Classification Approach to Predicting Healthy Recipes

Team Members: Hangyi Zhao, Bokyoung Son, Brandon Rocchio

Website Link: https://boson25.github.io/DSC259R_BBH-Horizon-Lab/

Introduction

In this project, we analyze a recipe dataset containing over 80,000 recipes, with features such as tags, descriptions, cooking time, number of steps, number of ingredients, and nutrition information. Our main question is whether we can predict if a recipe is healthy using information available in the recipe itself.

Data Cleaning and Exploratory Data Analysis

We define a recipe as healthy if it satisfies at least three out of four median-based nutrition conditions: low calories, low sugar, low saturated fat, and high protein. This creates a binary classification target, where 1 represents healthy and 0 represents unhealthy.

To avoid data leakage, the nutrition variables used to define the label are not used as model features. Instead, we rely on recipe tags, description text, and basic recipe information such as cooking time, number of steps, and number of ingredients. Because the dataset is imbalanced (about 70% unhealthy and 30% healthy), we use ROC-AUC as our main evaluation metric.

Assessment of Missingness

We examined missingness in the cleaned recipe dataset. The columns with missing values were name, description, and avg_rating. We argue that missingness in the description column is likely NMAR, since whether a user writes a description may depend on the description itself. For example, simple or quickly submitted recipes may be more likely to omit one.

We also tested whether missingness in avg_rating depends on observed variables. A permutation test comparing recipes with and without ratings found a statistically significant difference in cooking time, with an observed mean difference of 117.34 minutes and a p-value of 0.038. A second permutation test showed an even stronger relationship with n_ingredients, with a p-value close to 0.

These results suggest that missingness in avg_rating is at least partially MAR with respect to cooking time and number of ingredients. In other words, simpler and faster recipes are more likely to have missing ratings.

Hypothesis Testing

Our main hypothesis test asked whether average ratings differ between short recipes (less than 30 minutes) and long recipes (more than 60 minutes). The null hypothesis stated that there is no difference in average rating between the two groups, while the alternative hypothesis stated that there is a difference.

The observed mean difference in average rating was 0.0359 points (short minus long). Using a permutation test with 2,000 shuffles, we obtained a p-value below 0.0005. Therefore, we reject the null hypothesis at the 0.05 significance level.

This suggests that short recipes tend to receive slightly higher ratings than long recipes. However, the effect size is small, so while the relationship is statistically significant, it is not necessarily large in practical terms. A second hypothesis test comparing low-ingredient and high-ingredient recipes found no statistically significant difference in average rating.

Framing a Prediction Problem

We frame this task as a binary classification problem: predict whether a recipe is healthy. The response variable is is_healthy, which equals 1 if the recipe satisfies at least three of the following four conditions: low calories, low sugar, low saturated fat, and high protein.

The features used for prediction include recipe tags, description text, cooking time, number of steps, and number of ingredients. We intentionally exclude nutrition variables from the feature set because they are already used to define the target label, and including them would create data leakage.

We evaluate our models using ROC-AUC because the dataset is imbalanced: about 69.5% of recipes are labeled unhealthy and 30.5% are labeled healthy. ROC-AUC gives a better sense of ranking performance than raw accuracy in this setting.

Baseline Model

Our baseline model is a logistic regression classifier using only three numerical features: n_steps, n_ingredients, and log_minutes. This gives us a simple and interpretable starting point.

The baseline model achieved a ROC-AUC of 0.5844, only slightly above random guessing. This shows that recipe complexity and cooking time alone are weak predictors of healthiness. That makes sense intuitively, since a quick recipe is not always healthy, and a long recipe is not always unhealthy.

We then explored stronger feature sets. Adding TF-IDF features from recipe tags increased performance substantially to 0.7542, and adding description text further increased performance to 0.7642. These improvements show that textual metadata contains much more signal than simple structural recipe features.

Final Model

We compared several models on the richer feature set: logistic regression, random forest, and gradient boosting. Their ROC-AUC scores were 0.7642, 0.7682, and 0.7689 respectively, so Gradient Boosting performed best among the untuned models.

We then built a final pipeline using:

  • Numerical features: n_steps, n_ingredients, log_minutes, and n_steps_sq
  • TF-IDF features from tags_str
  • A GradientBoostingClassifier with hyperparameter tuning through GridSearchCV

GridSearchCV selected the best hyperparameters as: learning_rate = 0.1, max_depth = 5, and n_estimators = 200.

The final tuned model achieved a test ROC-AUC of 0.7837, improving on the earlier Gradient Boosting result of 0.7689. This improvement came from better feature engineering and model tuning. In particular, health-related tags such as “healthy” and “low-fat” were highly informative, and the squared steps feature helped capture non-linear complexity effects.

Overall accuracy increased to 0.75, although the model still performs better on unhealthy recipes than healthy recipes. This is consistent with the class imbalance in the dataset.

Fairness Analysis

To assess fairness, we compared model performance across two recipe complexity groups: simple recipes (number of ingredients less than or equal to the median) and complex recipes (number of ingredients above the median).

Using the Gradient Boosting model, we found:

  • AUC for simple recipes: 0.7660
  • AUC for complex recipes: 0.7653
  • Observed AUC difference: 0.0007

We then ran a permutation test to determine whether this difference could be due to chance. The resulting p-value was 0.9380, which is much greater than 0.05. Therefore, we fail to reject the null hypothesis that the model performs equally well across the two groups.

This suggests that our final model does not show meaningful performance disparities between simple and complex recipes.
